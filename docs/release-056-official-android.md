## Implementation and validation

- **Android and authentication.** The Expo/React Native release calls the same Supabase project and uses the same public client key as the web production configuration and the actual downloaded 0.5.4 bundle. The official artifact contains its own JS bundle, Internet permission and ARM64, ARMv7 and x86-64 libraries. Minimum SDK is 24 and target SDK is 36. Artifact checks found the production URL and key, no checked loopback Supabase endpoint, and none of the tested local private credential values or key container filenames. The 75 checked mobile runtime sources, modules, assets, configuration and dependency manifests in the build workspace matched RC1. Preparation now pins the production project, and CI checks the compiled client configuration and exact movie before accepting an APK.
- **Real accounts.** Separate production SDK sessions using the web and mobile client libraries returned the same verified user ID and role for each designated customer, provider and administrator. These checks signed in, read the caller's account context and signed out. They created no registrations, bookings, listings, messages or payment records. The app stores native sessions using its existing secure storage adapter. Administrative receipt review remains in the web workspace.
- **Backend and payments.** The mobile booking flow persists a draft, obtains the server price and confirms through the customer-scoped booking RPC. The database enforces a unique customer/draft idempotency key. Provider status transitions, participant messages, unread state, receipt access and approval use the existing RPCs, policies and private Storage. Focused mobile screens subscribe to Postgres changes and refresh on foreground and on a fallback interval. In-app Realtime notifications have staging coverage. Background OS push delivery has no acceptance evidence.
- **Isolated workflow results.** The disposable local Supabase stack passed all 15 browser integration cases on the RC1 backend. These included persisted booking and provider transitions, participant-only messaging, recipient notification delivery, receipt rejection and approval over Realtime, private files, role restrictions and test email registration/recovery. The local runner stopped its containers and removed its network. The embedded PostgreSQL suite passed 232 assertions. Web and mobile unit suites passed 33 and 37 tests respectively. No monetary transaction ran.
- **Opening.** The bundled movie matches the checked-in optimized derivative of `logo/LOGO ANIMATION/SerbisyoGoAnimation.mp4` byte for byte. It is 5.87 seconds, 720 × 1280, 30 fps, H.264 with stereo AAC. The native player fits the complete portrait frame on black without upscaling. Its process-wide guard prevents navigation replay. It uses media volume, mutes in silent/vibrate mode, and releases the startup route on completion, error, timeout, Back or interruption. Existing session routing selects Home or Sign in and preserves incoming deep links. The emulator smoke script now expects the optimized dimensions. Earlier emulator evidence covers a different build. Playback on the final signed bytes is pending.
- **Website.** The candidate static export shows SERBISYO GO and one Download for Android link using the reviewed release manifest. The QR code uses the same URL. Previously a published database row could supersede the reviewed GitHub artifact on this page. Administrative release storage and its permission checks still exist. The candidate page continues to identify 0.5.4 until official promotion. All four desktop and mobile-browser download checks passed, including starting the real download. Next.js exported 54 routes, the deployment preflight passed and Wrangler's dry run packaged 623 files.
- **Operational targets.** Cloudflare Worker `serbisyogo` serves the production hostname. Its deployment `2fe5ecc1-d42a-43a4-a284-c7c749bfd130` served version `a9a3a4fd-b1ce-4dc9-8c1a-6d45bf524f6e` at 100% on inspection. The website and Android project target Supabase project `qkopbbxmeqqzomrawltf`. Production remained on migration 023. The linked dry run listed only `202611190024_discovery.sql` and `202611190025_booking_communications.sql`, with no roles or seeds.
