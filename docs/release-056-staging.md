## Release controls and next steps

1. **Keep the two workflows disabled.** The operator reports manually disabling Cloudflare deployment and Android publication after the earlier inspection. The changes below exist in this working tree. When a repository administrator checks the hold, both read-only commands should return `disabled_manually`.

   ```sh
   gh api repos/Jawbear/SerbisyoGo/actions/workflows/cloudflare-deploy.yml --jq .state
   gh api repos/Jawbear/SerbisyoGo/actions/workflows/android-apk.yml --jq .state
   ```

2. **Review the local changes and select the release commit.** Include the workflows, their new helper scripts, migrations, client modules and tests. Keep unrelated `fixly/`, videos, local builds and credentials out of the review. Local HEAD is `0ef9745747084497269b74fddae99ed9ed9edefb` and the candidate includes uncommitted changes. Record the full SHA after the intended files receive review. Configure protection for main and restrict direct pushes and bypass. Remote review, merge and re-enablement are future owner actions.
3. **Configure approval outside the repository before enabling either workflow.** In GitHub Settings → Environments, configure `cloudflare-production`, `android-signing` and `android-production` with required reviewers, self-review disabled, admin bypass disabled and deployment branch `main`. Scope the Cloudflare token and account ID to `cloudflare-production`. Scope `ANDROID_RELEASE_KEYSTORE`, `ANDROID_RELEASE_PASSWORD` and `ANDROID_RELEASE_ALIAS` to `android-signing`. Remove broader copies of these secrets after verifying the environment configuration. Keep `ANDROID_RELEASE_CERT_SHA256` available as a repository variable for both signing and verification. Check Workers & Pages → production Worker → Settings → Builds for a separate Git deployment integration. Its current configuration remains unverified. [GitHub deployment environments](https://docs.github.com/en/actions/how-tos/deploy/configure-and-manage-deployments/manage-environments) · [Cloudflare build controls](https://developers.cloudflare.com/workers/ci-cd/builds/)
4. **Run staging on the reviewed source** with the command above. Record the candidate SHA, pending migration pair, before/after manifests, login and upload results, booking and payment state transitions, message and notification delivery, and access restrictions. Android additionally requires `artifact_run_id` from a completed successful Android run on the same commit and rechecks the tested APK and existing tag. A missing environment approval stops the job even if GitHub created the environment without reviewers. Obtain separate decisions for production migrations, web deployment and APK publication.
